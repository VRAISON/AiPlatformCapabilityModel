This map partitions the agent platform itself: the class of software that Codex, Claude Code, Copilot, Gemini CLI, Antigravity, Grok, Hermes, Qwen, and the Ollama model host each implement some part of.

Same three tiers. Business areas are the columns, business domains the groups, service domains the tiles. Each tile is one functional pattern on one asset, for example Agree · Folder. The color is prevalence across the nine homes on this machine and, from v2, across the runtimes' documented protocols and flags, not a build status. A designed path with no files yet still counts. A tile the product class has but no home evidences is marked open, so the map shows gaps and not only inventory.

How to read this against the other map

The engineering-OS landscape is about seats, the record, gates, and attestation. This one is about the platform a single agent product is. Authority is admission, identity, execution control, and configuration, not one policy. Memory is an instruction file plus an index, topic notes, retrieval, and a maintenance pipeline. A session is a catalog, a transcript, a resume set, a progress checkpoint, and a file rewind point. The agent's output on a codebase has its own area, Change & Review, because a coding agent that cannot isolate, attribute, and review its edits is not a platform.

Two splits keep the cells honest. Copilot's editor orchestrator is agent-host.db under VS Code user data, not only ~/.copilot; most of the Change & Review evidence comes from that process. Antigravity lives in ~/.gemini/antigravity-cli and is a different product from Gemini CLI. Ollama is the host row: weights and a REPL prompt list, with no session, grant, or memory service. Qwen is the client that points at it.

What the 2026-10-18 review challenged
  • Inventory, not model. The first draft only had tiles with files behind them, so a capability no home stores could not appear. An Open state now carries those tiles: transcript export, secret redaction, and an untrusted-content guard.
  • No home for the agent's work product. Changesets, edit attribution, worktree isolation, repository state, review annotations, code review, and pull requests were absent. Copilot's agent host, Grok's worktrees.db, Antigravity's annotations, and Codex's review plugin evidence them.
  • Native tools were missing. Shell execution, file edit, code search, and browser and computer use are the agent's hands. Browser use was filed as a surface; it is a tool.
  • Identity, settings, and policy were missing. Every product has a sign-in, a user settings file, project-level settings, and feature flags. Copilot's managed settings (MDM and account policy) and Claude's dangerous-mode flag are the managed-policy evidence.
  • Overlaps resolved. Fork and delegation cited the same spawn evidence; forking is now the user's branch of a conversation and delegation is the agent's. Remote Control and Shared Room both cited Hermes rooms. Checkpoint & Rewind merged Copilot's summary checkpoints with its file snapshots. Model Catalog merged what is available with what is chosen.
  • Reclassified. Session Catalog and Transcript Log are wide: every client stores them. Approval Mode is a configured stance, so Administer, not Agree. Hook and Document had asset equal to name.
  • v2: protocol and flag evidence. The first map read only what each home stores on disk, so capabilities that live in a runtime's protocol or flags were invisible. v2 adds a Turn Control domain (interrupt, steering, human input request, run and spend limit), headless runs and agent protocol servers, instruction precedence, system prompt override and context budget, agent credential and secret injection, plan and entitlement, retry and rate limit, peer message, event trigger, health check and plugin verification. Their evidence is the runtimes' documented protocols and flags (ACP, AHP, stream-json, app-server) as well as the homes. Persona & Role is split: a persona sets behaviour, a role sets responsibilities. An attributable action ledger, evidence and attestation, crew liveness, team assignment and handoffs stay on the sibling engineering map.
  • Left off on purpose. Lock files, command history, tip counters, theme, and onboarding flags, per the comparison spec. They describe usage hygiene, not the platform.
